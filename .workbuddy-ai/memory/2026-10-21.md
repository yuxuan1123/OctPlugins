## 内嵌浏览器（browser 插件）卡顿诊断（只诊断，未改代码）

核对 `ui/browser-panel.js`、`ui/index.html`、`ui/src/main.ts`、`ui/src/renderer.ts`、
`mvp_test/plugins/plugins/browser/{main.js,ui/*}`。

用户列的 7 条问题核对结论：
- 成立：标签/面板从不休眠卸载（webview 只在 tabRemove 时 remove）；`.bpanel` 非激活时仅
  `visibility:hidden`（display 一直 flex，唯一例外是 `body.settings-window` 时 `display:none !important`）；
  `.b-page.hidden` 只 visibility；openUrl 默认新开标签且任务标签永不回收；全部 webview 与宿主 chrome
  同在主窗渲染进程 + 同一棵合成树（main.ts:415 nodeIntegration+webviewTag）。
- 部分不成立：同步 webview API 那条机制写错了——getURL/canGoBack/getWebContentsId 是 sync IPC 到
  **主进程**（值多为浏览器进程侧缓存），不会因 guest JS 忙而阻塞宿主；影响远小于描述。
- 成立但属放大器：feTurbulence + mix-blend-mode、顶栏 backdrop-filter。

补充发现（用户未提）：
1. `createTab` 直接设 src 后 append，后台标签立刻开始加载（无 lazy），启动时 3 个飞书并发加载。
2. `.b-page` 全是 `position:absolute; inset:0` 满尺寸 → 每个隐藏标签保留整窗合成表面；resize 时全量 resize。
3. `.panel.active` 的 `fade` 动画（opacity+transform 250ms）作用在包含全部 webview 的 `.bpanel` 上。
4. `allowpopups` + `setWindowOpenHandler` 一律 deny → window.open 全变新标签且不关，guest 里 window.open 返回 null。
5. `crashed` 只改标题，不销毁不重载；无 render-process-gone，僵尸 webview 常驻。
6. 无 `will-attach-webview` 加固；`ui/index.html` 无 CSP（browser.md §9 声称有，文档漂移）。
7. `browserSend()` 每个浏览器事件都强制 `ui:switch-panel` → 定时任务把用户从别的插件拽回浏览器。
8. `renderer.ts:1305` 每个 kernel 事件 `console.log(p.data)`（tool 事件还 console.warn），与浏览器 chrome 同主线程。
9. `showPanel` 全量 toggle `.panel` class → 每次切面板全窗口样式重算 + bpanel 合成树重分层。
10. 无标签上限、无 LRU discard；chrome-tabs `addTab` 每次 `layoutTabs()` O(n) 强制布局。
11. 插件 iframe 同样从不卸载（display:none 不停 JS），OIM/翻译的 WS 与定时器常驻。
12. `showTab` 的 `wv.focus()` 在 webview 未 attach 时无效。

修复方向（未实施）：隐藏超时后 `wv.remove()` 并记 URL，切回重建（Chrome tab discard）；后台标签延迟加载；
标签上限 + 任务标签自动关；去掉 bpanel 上的 fade 动画；迁移 WebContentsView。

## 插件目录 vs 宿主代码 的责任边界（结论）

**重要：`mvp_test/plugins/plugins/browser` 是快照副本，不是生效的那份。**
- 它的 `main.js` require `../../sdk/node/src` → 解析到 `mvp_test/plugins/sdk`（不存在），单独跑必崩；
- `package.ps1:98` `$pluginSrc = <root>\plugins`；生效的是 `plugins/browser/`。
- 两份 `main.js` / `ui/app.js` 内容完全相同（diff 无差异），改错目录等于白改。

插件进程能力边界：`sdk/node/src/index.js:63-67` 只有 `channel.call`（registry.call）、`channel.emit`
（event.emit）、`gate.*`（文件/exec）。**没有任何宿主 IPC**，不能关标签、不能卸 webview。
宿主只把 `browser.open` / `browser.shell` 两个事件映射成动作（main.ts:1084-1093）。

只改插件目录能做的仅 3 件：
1. `main.js:12-16` DEFAULT_STARTUP 3 条 → 1 条（唯一有实质收益的插件侧改动，省 2 个飞书进程）。
2. `main.js:55` `activate:true` → false（只防抢标签焦点，防不住 browserSend 的 switch-panel）。
3. main.js 里自建任务排队/节流（仅对定时任务生效）。

坑：**插件返回空清单无效** —— `browser-panel.js:370-371` 有 `finalList = list.length ? list : FALLBACK_STARTUP`
兜底，清空必须改宿主。所以"插件侧最多 3→1，做不到 0"。

必须改宿主 `ui/`：discard/lazy/标签上限/crashed 重建/面板隐藏策略/fade 动画/blend 特效/
switch-panel 强制切页/renderer 的 console.log 与全量 class toggle/WebContentsView 迁移。
`ui/browser-panel.js` 属于宿主，不属于插件——这是最容易误判的一处。

## WebContentsView 迁移范围

**只涉及 browser 一个面板，其他插件不需要也不应该迁。**
- 全项目仅 `ui/browser-panel.js:59` 创建 `<webview>`；其他插件 UI 是 `renderer.ts:183-191` 的 iframe
  （src = `KERNEL_BASE + plugin/<pid>/ui/index.html`，透明背景 + border-radius:14px + 继承 `/res/theme/plugin.css` 变量）。
- WebContentsView 是 `<webview>` 的替代品，与 iframe 无关。迁过去会失去：主题变量继承、透明/圆角、
  z-index 可控（原生层恒在 host HTML 之上）、浮层可覆盖。
- 代价集中在宿主窗口结构：`main.ts` 的 createWindow 要改成 BaseWindow 或 BrowserWindow.contentView
  加子 view；新增「渲染进程上报视口 rect → 主进程 setBounds」的 IPC，面板切换/resize/侧栏折叠都要同步；
  命令面板、设置弹窗、下拉、tooltip 出现在浏览器区域时会被原生层遮住，必须开浮层时把 view 移出。
- 收益：discard 变简单（从 contentView 移除即可），且脱离 webviewTag + nodeIntegration 的组合。

## 窗口缩放卡顿的分层归因（未改代码）

- 层1 guest 自身重排/重绘：`.b-page{width/height:100%}` 且无 `disableguestresize` → 每个 live webview 每帧跟随新尺寸，
  飞书 Sheets 这类页面单帧 layout+raster 很贵。**架构无关，换 WebContentsView 也在**。
- 层2 webview bounds 同步：宿主 renderer→browser→guest 的异步 IPC，宿主已画新帧、guest 还是旧尺寸 → 视觉上拉伸后跳正。
  WebContentsView 的 setBounds 少一跳、与宿主 DOM 合成解耦，能改善但非零成本。
- 层3 宿主全窗合成：`body::after` 固定全屏 + `mix-blend-mode:multiply`（index.html:39-41）、`header` `backdrop-filter:blur(6px)`（:49）。
  上一轮只在 `body.browser-active` 时关掉（:279-280）→ 在 home/设置面板缩放时层3 全开，**与 WebContentsView 完全无关**。
- 无任何 resize 监听/防抖（grep 无结果），所以不是 JS 造成的。
- 便宜替代方案（未实施）：隐藏 live webview 加 `disableguestresize`；缩短切走 discard 阈值使 live guest 常态=1；
  拖拽期间用旧帧占位（Chrome 做法）。

## 结论：WebContentsView 现在不必迁（决定）

主要痛点（用久了卡 / 切面板顿）已由 discard+lazy+fade 修复；缩放卡的层1（guest 重排）换架构也在，层3 与架构无关。
迁移的收益只剩「少一跳 IPC + 生命周期更干净 + 可关 webviewTag」，代价是浮层遮挡（命令面板/设置弹窗/tooltip）
与 bounds 同步这套新回归面。**触发条件**才做：需要多窗口/拖出成窗/分屏；webview 在新 Electron 被弃用；
缩放跟手成为主要抱怨且 disableguestresize/占位帧 无效；需要 per-tab 的 session/权限/音频控制。
注意：迁 WebContentsView **不会**顺带解决宿主 `nodeIntegration:true + contextIsolation:false` 的安全债。
